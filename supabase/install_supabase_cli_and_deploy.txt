SUPABASE CLI + DEPLOY NOTES
Project ref: lsamggztfizmkyljdgwq   (URL: https://lsamggztfizmkyljdgwq.supabase.co)

-- CLI ---------------------------------------------------------------------
`npm install -g supabase` is NO LONGER SUPPORTED by Supabase. Use npx, which
needs no install and always runs the current version:

    npx supabase@latest --version
    npx supabase@latest login          # opens a browser for the access token

Run every command below from the ROOT of this repo (the dir containing
supabase/functions/), and pass --project-ref rather than running `link` — link
prompts for the database password and isn't needed just to deploy functions.
(The old note here passed a full URL to --project-ref, which the CLI rejects;
it wants the bare ref.)

-- DEPLOY FUNCTIONS -------------------------------------------------------
    npx supabase@latest functions deploy weekly-digest          --project-ref lsamggztfizmkyljdgwq
    npx supabase@latest functions deploy unsubscribe            --project-ref lsamggztfizmkyljdgwq
    npx supabase@latest functions deploy send-temp-password     --project-ref lsamggztfizmkyljdgwq
    npx supabase@latest functions deploy moderator-delete-media --project-ref lsamggztfizmkyljdgwq
    npx supabase@latest functions deploy community-invite-email --project-ref lsamggztfizmkyljdgwq

community-invite-email needs JWT verification ON (the default) and no extra
secrets: RESEND_API_KEY is already set, and the two optional ones below have
working defaults. It invites AS the caller, using their JWT, so the
permission check is community_invite's own — do NOT deploy it with
--no-verify-jwt, which would turn it into an open relay for "you have been
invited to BirdWatchAI" to any address on earth.

Until it is deployed the community panel still invites people correctly; it
just says plainly that no email went out.

Licensing (see functions/gumroad-license-webhook/README.md for the full
runbook). The --no-verify-jwt flag is MANDATORY here: Gumroad's ping carries no
Authorization header, so without it every sale gets a 401 and no license key is
ever issued.

    npx supabase@latest functions deploy gumroad-license-webhook --project-ref lsamggztfizmkyljdgwq --no-verify-jwt

If the CLI rejects --no-verify-jwt (it moved into config.toml in newer
versions), deploy without it and turn JWT verification off in the dashboard:
Edge Functions -> gumroad-license-webhook -> Settings -> Verify JWT = off.

-- SECRETS ----------------------------------------------------------------
Set these in the DASHBOARD (Edge Functions -> Secrets), not on a command line.
Multi-line values like the license PEM get mangled by shell quoting, and a
mangled PEM fails on every sale. The dashboard textarea takes a paste as-is.

    RESEND_API_KEY              re_...          (shared by all mail functions)
    DIGEST_FROM_EMAIL           BirdWatchAI Weekly <digest@birdwatchai.com>
    SITE_URL                    https://joebarraco.github.io/birdwatchai-releases

Community invites (both OPTIONAL — the defaults in the function are correct
for the live site, so set them only to change them):
    INVITE_FROM_EMAIL           BirdWatchAI <noreply@birdwatchai.com>
    COMMUNITY_URL               https://www.birdwatchai.com/docs/community.html

Licensing:
    LICENSE_PRIVATE_KEY_PEM     -----BEGIN PRIVATE KEY-----...   (whole PEM)
    LICENSE_FROM_EMAIL          BirdWatch AI <licenses@birdwatchai.com>
    GUMROAD_PING_TOKEN          long random string; also goes in the ping URL
    GUMROAD_PRODUCT_ID          every license-bearing product, comma-separated
    GUMROAD_ACCESS_TOKEN        Gumroad -> Settings -> Advanced -> Applications
    GUMROAD_REQUIRE_CALLBACK    set to 1 after the first successful test sale

-- NEVER PUT SECRETS IN THIS REPO ----------------------------------------
This repo is PUBLIC — it serves www.birdwatchai.com via GitHub Pages. Anything
committed here is world-readable, permanently, including in git history.
Secrets belong in the Supabase dashboard only.

(This already happened once. A Resend key was pasted into this file and into
supabase/resendapikey.txt, making it world-readable from Apr 2026 until
2026-08-17. RESOLVED: that key was revoked in Resend, a replacement was issued
with Sending-access scope restricted to birdwatchai.com, and RESEND_API_KEY was
updated. The dead key is still visible in history under 24a2616 and 3ca56fc —
harmless now that it's revoked, which is why no history rewrite was done. The
lesson it paid for is the rule above.)
